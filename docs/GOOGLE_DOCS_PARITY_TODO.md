# OpenDoc → Google Docs/Sheets Replacement: Gap Analysis and TODO

**Status: gap list, re-verified against the working tree on 2026-09-09.** Originally generated 2026-09-03 from nine parallel code audits (text editing, formatting/layout, embedded objects, collaboration, files/storage/import/export, spreadsheet, app shell, build/test health, plans-vs-code). `docs/RESTRUCTURE_PLAN.md` remains the active restructure tracking plan; this file is the parity gap inventory that feeds it. IDs are stable and are never renumbered — tick items here as they land.

Since the original audit the tree was restructured: `crates/opendoc-app-api/` (one 57k-line file) no longer exists. Its contents are split across `crates/opendoc-app/src/*.rs` (services and `*_commands.rs` groups behind the `OpenDocApp` facade), `crates/opendoc-api/` (command registry, arg DTOs, JSON parsing, contract generator), `crates/opendoc-spreadsheet/` (workbook model, formula engine, recalc), and `crates/opendoc-render/` (HTML projections). The frontend was rewritten from ~36k lines of TypeScript to ~2.9k: `main.ts` is screen composition, `editor.ts` a DOM selection/diffing adapter, `invoke.ts` transport only, and the former 14k-line JS mock backend was replaced by a real WASM build of the Rust core (`crates/opendoc-wasm`).

Because of that restructure, **line numbers from the 2026-09-03 audit have been dropped**; items cite file + symbol/function instead.

Abbreviations: `main.ts` = `apps/desktop/src/main.ts`; `editor.ts` = `apps/desktop/src/editor.ts`; `invoke.ts` = `apps/desktop/src/invoke.ts`; `ui.ts` = `apps/desktop/src/ui.ts`; `app` = `crates/opendoc-app/src/` (named module, e.g. `app/editor.rs`); `api` = `crates/opendoc-api/src/` (`api/commands.rs` is the command registry); `core` = `crates/opendoc-core/src/lib.rs`; `sheet` = `crates/opendoc-spreadsheet/src/`; `render` = `crates/opendoc-render/src/lib.rs`; `merge` = `crates/opendoc-merge/src/lib.rs`; `store` = `crates/opendoc-store/src/lib.rs`; `import` = `crates/opendoc-import/src/` ; `citations` = `crates/opendoc-citations/src/`; `sign` = `crates/opendoc-sign/src/lib.rs`.

Verification notes: `_(done YYYY-MM-DD: …)_` records work that closed an item. `_(verified 2026-09-09: …)_` records that an item was re-checked against the current tree on that date and found already closed.

Priority: **P0** = blocks daily use as a Docs/Sheets replacement. **P1** = important for parity. **P2** = nice to have or polish.

Status tags: **BROKEN** = exists but does not work correctly. **MISSING** = not present. **PARTIAL** = present but incomplete.

## 1. Executive summary

The Rust core (content-addressed storage, manifests, candidate heads, signing, single-process merge with a large convergence test suite, a 252-function formula evaluator with a real dependency graph, Google-API-shaped JSON import/export, a `zip`+`quick-xml` DOCX importer, hayagriva-backed CSL citations) is real and tested: `cargo test --release --workspace` is green at 362 tests.

**What changed since the 2026-09-03 audit.** The editor substrate was rebuilt: the document body is a single `contenteditable` host, Rust owns editing semantics (`app/editor.rs` `apply_editor_input` over a `{block_id, inline_id, offset}` selection model with character-level operations, grapheme-aware deletes and word boundaries), HTML is generated in Rust (`render`) and patched in with a keyed DOM morph (`editor.ts` `morphChildren`), and one gesture is one IPC and one undo checkpoint. `window.prompt` is gone — `ui.ts` provides real `<dialog>` modals, and `tauri-plugin-dialog` gives native open/save pickers with `<input type="file">` in the browser. The 14k-line JS mock backend was deleted and replaced by a real WASM build of the same core (`crates/opendoc-wasm`, `npm run build:wasm`). Images render as data-URL `<img>`, footnotes render numbered at the foot of the body, suggestions and comment ranges render inline, print works (`window.print()` plus `@media print`), HTML/text/JSON export writes real files, and the unsaved-changes guard covers quitting. Tooling caught up too: `npm run verify` runs `cargo fmt --check`, `clippy -D warnings`, the workspace tests, a generated-contract drift check, `tsc --noEmit`, the WASM build, the static build and a jsdom smoke test against the real WASM core; CI runs all of that plus a native Tauri check. The twelve competing plan documents were archived.

**What still blocks the premise.** The document model has gained nothing: no paragraph alignment, indent, line spacing, page setup, headers/footers, sections, checklists or pagination — `Block.properties` is still never populated. Equations render as raw LaTeX. There is no PDF or DOCX export, no version history, no real-time transport, no server, no identity, and authorization is still computed from client-supplied grants. Merge replays operations in lexical `(actor, seq)` order with no offset transformation, so concurrent edits still land in the wrong places. Several spreadsheet features are *written but unwired*: row/column shifting, sort, formula-shifting paste and a CSV/XLSX codec all exist in `opendoc-spreadsheet` with no command reaching them, and computed number formats are never rendered. Test coverage fell from 653 to 363 as the monolith was split, leaving `opendoc-app` (18 tests) and `opendoc-spreadsheet` (6) thinly covered.

### The ten things that block the premise (all P0)

1. **No paragraph or page model.** No alignment, indent, line spacing, page size/margins, headers/footers, page numbers, sections, checklists or pagination. One model change unblocks a dozen items. (§3 FM-19..FM-22, FM-33, FM-37, FM-40, FM-41, FM-47)
2. **Merge has no causal order and no offset transformation.** Character-level ops exist, but a `BTreeMap` keyed on `(actor, seq)` decides order and offsets are never transformed, so two machines still converge to the wrong text. ADR 0001 promised a CRDT. (§5 CO-3, CO-4; §10 PL-3)
3. **No version history.** No manifest-addressed command, no open-at-version, no restore, no diff — `ManifestRecord.parent` is walked only by merge internals. (§5 CO-16)
4. **No real-time transport, presence, identity, or server.** Authorization, sharing, relay sync and the lookup index are all pure functions of caller-supplied arguments. (§5 CO-8, CO-9, CO-10, CO-15, CO-18, CO-19, CO-44)
5. **Equations never render.** No math engine; `render` emits escaped LaTeX source. (§4 OB-23, OB-24, OB-42)
6. **Table structure is row-only.** No column operations anywhere in `merge`, no merge/split cells, no widths, no cell styling, and no doc-table UI at all. (§4 OB-21)
7. **Spreadsheet: written but unwired.** Row/column delete still leaves gaps and nothing shifts, positional insert, one-off sort, formula-shifting paste and the CSV/XLSX codec all exist in `opendoc-spreadsheet` but no command reaches them; computed number formats and TRUE/FALSE are never rendered; no fill handle. (§8 SH-1, SH-7, SH-11, SH-28, SH-30, SH-38, SH-47)
8. **No PDF or DOCX export, and no non-Word import.** Export is Google Docs JSON, HTML and plain text; import is `.docx`/`.doc` only, and Google Docs JSON import still aborts on any real-world document. (§6 FS-10, FS-21, FS-22, FS-23, FS-24)
9. **Unsaved work is still losable.** Quitting is guarded, but `open-repository`, `open-recent`, `import-word` and `import-json` discard silently, autosave does not run before the first manual save, and there is no crash journal. (§6 FS-6, FS-7, FS-41)
10. **Coverage regression.** The split from the 57k-line monolith dropped the suite from 653 to 363 tests and left the new service and command modules (`opendoc-app` 18 tests, `opendoc-spreadsheet` 6) barely tested; there is still no real-browser e2e. (§9 QA-3, QA-6)

## 2. Core text editing (ED)

Architecture: the document body is one `contenteditable` host (`main.ts` `renderMain` appends `editorHost` into `.page`; `editor.ts` `DocumentEditor` sets `contenteditable` and `role="textbox"` on it). Rust renders the whole body to HTML (`render` `render_document_html`; blocks keyed by `data-block-id`, runs by `data-inline-id`, atomic inlines `contenteditable="false"`), and the frontend patches it in place with a keyed DOM morph (`editor.ts` `morphChildren`), so caret, IME state and scroll survive updates. Input is captured as `beforeinput`/`compositionend`/`paste` gestures, queued and serialized (`DocumentEditor.enqueue`/`pump`); each gesture is a single `apply_editor_input` IPC carrying an `EditorSelection` of `{block_id, inline_id, offset}` positions (`api/editor.rs`). Editing semantics live in Rust: `app/editor.rs` builds a `DocumentIndex` over the block tree, resolves the selection to character offsets, and accumulates one `EditPlan` batch of typed operations (`insert_text`, `insert_multiline`, `split_block`, `delete_range`, `delete_backward`/`delete_forward` with grapheme and word boundaries), returning the new document plus the caret in `EditorResult`. Marks go through `apply_editor_mark`; selection queries through `app/editor_selection_service.rs`. `app/dispatch.rs` enforces the per-command `undoable` flag with 1 s coalescing over a 200-entry snapshot stack (`app/state.rs` `checkpoint`, `UNDO_STACK_LIMIT`).

## 3. Text formatting, paragraph formatting, page layout (FM)

Model: flat `Vec<Block>` with `BlockKind ∈ {Paragraph, Heading{level}, ListItem{list_id, level, ordered}, Table, EquationBlock, Image, PageBreak}` and a still-never-populated `properties: Vec<Property>` (`core` `Block`, `BlockKind`, `Property`; the only writes anywhere are `properties: Vec::new()` initialisers). Marks: Bold, Italic, Underline, Strike, Code, Superscript, Subscript, Color, Background, Font, Size, Link, Citation (`core` `MarkKind`). `Document` is `uuid, title, locale, doi, blocks, footnotes, comments, suggestions, citation_database, warnings` — no `sections`, `styles`, `default_style`, page setup, or headers/footers. HTML is produced in Rust by `render` `render_document_html` (`Renderer::render_blocks` + `ListWriter`), which groups consecutive list items into real nested `<ol>/<ul>` with per-list `value` numbering and emits inline `style` for valued marks (`write_mark_style`); paragraph-level formatting has nothing to render. Block-style editing is command-driven (`set_editor_selection_block_style`, `set_block_text_style`, `update_list_item`, `adjust_editor_selection_list_indent`, `apply_editor_mark` in `app/document_commands.rs` and `app/editor.rs`). The registry (`api/commands.rs`) contains **no** alignment, paragraph-indent, line/paragraph-spacing, page-setup, header/footer, section, column, checklist, TOC, or named-style command — FM-19..FM-25, FM-27, FM-37, FM-40..FM-43 are all one missing model change, not a dozen independent ones.

## 5. Collaboration, review, history, sharing, signing (CO)

There is still no collaboration runtime: no transport crate, no server, no live presence, no version list. What changed since the audit is the boundary, not the capability. Every collaboration DTO now lives in `api/runtime.rs` (`OpenDocRuntimeSession`, `OpenDocAuthorizationDecision`, `OpenDocShareInvite`, `OpenDocSyncRelayResult`, `OpenDocRuntimeLookupResult`) and is reached through the one command registry (`api/commands.rs` → `app/dispatch.rs`); each is a pure function of caller-supplied arguments, so authorization, sharing, relay sync and the lookup index remain local simulations (see ADR 0004 and `CLAUDE.md`). The frontend dropped the fake collaboration UI entirely: `main.ts` no longer sends relay operations, presence, grants or candidate merges — `case "share"` toasts that sharing needs a server. The single-process core did get real work: `StableId::new` mixes a per-process nonce, `next_seq` is rebased on open, `merge` gained character-level `InsertText`/`DeleteText`, `accept_all_suggestions`/`reject_all_suggestions` are Rust batch commands, candidate merging is a three-way merge over `store` `plan_candidate_merges` + `app/repository_io.rs` `operation_delta_since_base`, `render` marks comment ranges (`has-comment`) and suggestions (`suggested-insert`) inline, anchors project quoted text (`app/document.rs` `anchor_display_label`), operation records carry wall-clock `created_at_ms` (`app/journal_service.rs`), and local/flat stores take a `HeadLock` for CAS. Merge order is still lexical `(actor, seq)` replay with no offset transformation, comment "resolve" is still deletion, comment timestamps are still sequence numbers, undo is still whole-document checkpoints, and trust still requires the signer's private key. CO-1..CO-4 in the original audit were **(verified by running)**.

## 6. Document lifecycle, storage, import/export, printing (FS)

The storage core (content-addressed objects, manifests, CAS heads, candidates, hash verification, pack compaction) is real and is now reachable from a real shell: `save`, `save-as`, `open-repository`, `import-word`, `import-json` and `export-*` in `main.ts` `runAction` go through native pickers (`invoke.ts` `pickOpenPath`/`pickSavePath`/`openFile`/`saveFile`, backed by `pick_open_path`/`pick_save_path`/`read_file_base64`/`write_file_*` and `tauri-plugin-dialog` in `src-tauri/src/main.rs`), and the browser build runs the same Rust core as WebAssembly (`crates/opendoc-wasm` `dispatch`) rather than a JS mock. ## 8. Spreadsheet (SH)

The spreadsheet lives in its own crate, `opendoc-spreadsheet`: `model.rs` (`Sheet`, `Cell`, `CellFormat`, `CellValidation`, `SheetFilter`), `workbook.rs` (`SpreadsheetWorkbook`; sheet/row/column/named-range/merge/filter/protected-range mutation), `formula.rs` (A1 tokenizer and recursive-descent parser producing an `Expr` tree with `BinaryOp::Concat`/`Pow`, `UnaryOp::Percent`, array literals, and optional-axis `CellCoord` for `A:A`/`1:1`), `value.rs` (`FormulaValue::{Blank,Number,Text,Bool,Error,Array}` and `FormulaError` with Google's standard codes), `functions.rs` + `functions_legacy.rs` + `functions_legacy_tail.rs` (dispatch through `functions::call_inner`/`call_values`, falling through to `functions_legacy::evaluate_function`), `recalc.rs` (one workbook-wide dependency graph, `tarjan_order` SCC ordering, `RecalcState` incremental re-evaluation, array spill, `refresh_display_values`), `format.rs` (`Locale`, `format_with_pattern`, `format_date_pattern`, `display_value`, and an unused `parse_input`), `address.rs`, `lookup.rs`, `selection.rs`, `structure.rs`, `io.rs` and `google.rs`. `opendoc-app` wraps it: `spreadsheet_service.rs` `SpreadsheetMutationService::mutate`, `spreadsheet_commands.rs` (model commands), `spreadsheet_ui.rs` (selection-shaped commands), `spreadsheet_replay.rs` (envelope replay and merge). The grid is rendered server-side by `render` `render_workbook_html`; `main.ts` (`renderSheets`, `bindSheetEvents`, `onGridKey`) only morphs that HTML into the DOM and forwards selection/clipboard/format actions. 252 function names are recognised (§8.5).

**Two whole modules are implemented but dead**, which is why several items below read "written but unwired" rather than "missing": `structure.rs` exposes `sort_range`, `transform_formula_for_paste` and `shift_relative_references` with no callers outside itself (`insert_axis`/`delete_axis` were wired up on 2026-09-11); `io.rs` exposes `parse_csv`/`export_csv`/`import_xlsx`/`export_xlsx` (calamine, rust_xlsxwriter) that nothing outside the crate references. Likewise `format::parse_input` and `Cell.display_value` are computed but consumed by no command and by no renderer.

## 12. Suggested order of attack

Steps 1-5 of the original order are done (build green, data-loss guards on quit, unique IDs and sequence rebase, file dialogs and the blob→UI path, and the editor substrate rewrite). What remains, in order:

1. **Close the data-loss stragglers** (FS-6, FS-7, FS-41): guard `open-repository`/`open-recent`/`import-word`/`import-json`, autosave before the first manual save, crash journal.
2. **Paragraph/page model** (cross-cutting D): alignment, indent, spacing, real list ids with restart/continue, checklists, page setup, headers/footers, sections (FM-5, FM-19..FM-22, FM-27, FM-33, FM-37, FM-39, FM-40). Then pagination (FM-47) and, on top of it, PDF export (FS-21).
3. **Wire up what the spreadsheet crate already has** (SH-1, SH-7, SH-11, SH-30, SH-38, SH-47): adopt `structure::insert_axis`/`delete_axis`/`sort_range`/`transform_formula_for_paste`, render `Cell.display_value` instead of `computed_value`, and expose `io.rs` CSV/XLSX behind commands. Then the genuinely missing SH-28 (fill handle), SH-31, SH-35, SH-36.
4. **Table structure** (OB-21): column operations in `merge`, merge/split cells, widths, cell styling, and a doc-table UI (OB-7, OB-8, OB-22, OB-38).
5. **Equations** (OB-23, OB-24, OB-42): a math renderer, an editor UX, and LaTeX validation.
6. **Menu/toolbar completion on top of the new paragraph model** (UI-14, UI-16, UI-17, UI-44) and the removed chrome that has to come back (UI-6 outline, UI-28 ruler, UI-5 context menus).
7. **Clipboard fidelity and find** (ED-16, ED-29, ED-30, ED-31; move find/replace matching into Rust — ED-24, ED-25, SH-66).
8. **DOCX export and format breadth** (FS-22, FS-23, FS-24), plus a Google Docs importer that survives real documents (FS-10) with a real fixture (PL-12).
9. **Version history** (CO-16): expose manifest-addressed reads, then the UI (UI-27) and named versions/diff.
10. **Comments and suggestions UX** (CO-5, CO-22..CO-27): a `resolved` field, mode switch, structural suggestions, sidebar navigation.
11. **Causal ordering and offset transformation** (CO-3, CO-4, SH-9), plus the ADR that records what merge actually does (PL-3).
12. **Collaboration runtime** (CO-8, CO-9, CO-10, CO-15, CO-18, CO-19, CO-44): the service crate ADR 0004 defers, with server-owned authorization, presence and identity.
13. **Restore test coverage and add real e2e** (QA-3, QA-6): tests over `opendoc-app`/`opendoc-spreadsheet`, a browser runner, fixtures (QA-15).
14. **Packaging** for macOS/Windows, dark-mode wiring, settings, i18n (UI-38, UI-31, UI-32, UI-33).
15. **Storage breadth** (FS-27, FS-29, FS-32, FS-34, FS-39): deletion/trash, the S3 backend ADR 0002 calls the long-term default, GC, document metadata, compression.
